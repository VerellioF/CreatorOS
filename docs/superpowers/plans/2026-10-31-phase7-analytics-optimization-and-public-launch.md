# Phase 7: Analytics, Optimization & Public Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-grade Content Analytics & AI Diagnostics engine (supporting real connected platform metrics and transparent manual inputs, zero fabricated metrics, and traceable recommendations), complete public launch hardening (security audit, load testing, performance optimizations, error monitoring, backup/recovery verification, data retention policy), legal integrations (Privacy Policy, Terms of Service), and a functional user support workflow.

**Architecture:** A comprehensive public launch subsystem comprising: (1) normalized PostgreSQL tables for content performance snapshots, AI analytics insights, support tickets, and data retention logs with 100% RLS tenant isolation; (2) an Analytics Service supporting multi-platform aggregation (TikTok, Instagram, YouTube, Facebook, Shopee Video), performance history time-series, and strict data source provenance; (3) an AI Analyst Service diagnosing top/weak performers, content patterns, audience response, strategy alignment, and traceable recommendations; (4) automated security audit and load-testing suites verifying zero vulnerabilities and sub-250ms response times; (5) production reliability tooling including Sentry-ready error monitoring, liveness/readiness health probes, tested database backup/restore scripts, and automated retention cleanup; (6) integrated legal documents (`/privacy`, `/terms`) and user support ticketing (`/support`); and (7) a responsive, dark/light theme cohesive UI (`/analytics`).

**Tech Stack:** Next.js 15 App Router, TypeScript (strict mode), PostgreSQL 18.4 + Supabase RLS, Zod, Tailwind CSS, Lucide icons, Vitest.

**Spec:** Phase 7 Requirements from User Request & `docs/PRODUCT_REQUIREMENTS.md`, `docs/SYSTEM_ARCHITECTURE.md`, `docs/DATABASE_SCHEMA.md`.

## Global Constraints

- TypeScript in `strict` mode with zero unescaped `any` types.
- All database tables must have 100% Row Level Security (RLS) isolating rows by verified `workspace_id`.
- Zero service-role keys leaked to client bundles (`process.env.NEXT_PUBLIC_*`).
- Zero fabricated metrics: if metrics (clicks, conversions, retention) are unavailable, they must be `null` and displayed transparently as "Belum ada data" / "Not Available".
- Data sources must be strictly identified (`connected_account`, `manual_entry`, `api_sync`).
- AI recommendations must be traceable with explicit evidence citing specific posts, metrics, or strategy pillars.
- All existing 28 test suites and 156 tests must remain passing.

## Review Focus

1. **Zero Fake Metrics & Data Provenance:** When displaying views, engagement, clicks, or conversions, the system must clearly label whether data originates from an authenticated social account or a manual creator entry; unavailable metrics must never be populated with fabricated numbers.
2. **Traceable AI Diagnostic Recommendations:** Every recommendation generated by the AI Analyst must cite specific evidence (e.g. comparing top post hook styles vs drop-off retention in weak posts) rather than generic platitudes.
3. **Database RLS & Tenant Isolation:** Multi-tenant security audit must verify that no workspace can access, view, or modify another workspace's analytics snapshots, insights, support tickets, or retention logs.
4. **Disaster Recovery & Backup Verifiability:** Backup scripts must generate valid, checksum-verified dumps, and the recovery procedure must be demonstrably tested to restore state without corruption.
5. **Production Build & Performance Gates:** Next.js production build (`npm run build`) must succeed with zero errors and security headers (`CSP`, `HSTS`, `X-Content-Type-Options`) must be enforced.
